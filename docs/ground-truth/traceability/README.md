# Traceability Matrix

Source: `C20_E.C.H.O._MT.xlsx`, v1.0. See the [document register](../document-register.yaml).

`mt.json` contains requirement-keyed records from both source sheets. Each `source_row` is the original Excel row (1-based, including the header). The source sheet names are declared in `source.sheets`. Relational fields preserve the original Italian cell labels and order, split on semicolons with surrounding whitespace trimmed. `rad_notes` preserves the original note cell. `Non specificato`, `Nessuno` and `N/D` are source markers, not identifiers; they distinguish unspecified, none and unavailable. Empty arrays represent empty cells. Requirement names, descriptions, actors and priorities are not duplicated here; consult the RAD for normative requirements and the original matrix for the source cells.

`target_files` lists derived repository locators relative to `docs/ground-truth/`, including the requirement's own file. These are retrieval aids, not additional approved traceability relationships. Subsystem names and explicitly named architecture components are mapped to their extracted files; service labels remain in the source fields. `unresolved_references` records source references that lack an exact extracted target or refer to intentionally excluded mock-ups. A partially resolved reference may have both a locator and a note. Do not infer missing links or silently alias names.

Retrieve records by requirement ID; load only relevant target files and applicable cross-cutting constraints. Follow diagram references and subsystem dependencies as needed. Reverse lookups may be computed over the source fields; do not assume the two sheets declare identical inverse relations. Consult the original workbook only for a material unresolved discrepancy, as defined in the [ground truth rules](../README.md). See [known issues](known-issues.md). Missing or inconsistent links require escalation only when materially relevant to the task. TP/TCS links require explicit source relationships.
